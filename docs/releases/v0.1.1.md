# FailureLab v0.1.1

Security patch for the CI investigation workspace, September 12, 2026.

## Changes

- Origin validation now checks scheme, hostname, and effective port. Malformed and
  duplicate origins are rejected, and unrelated localhost origins cannot create cases.
  The Vite development proxy continues to work with matching Host and Origin headers.
- Removed the production Host exception for the test client's default hostname.
  Tests now use a loopback address. Security headers also cover rejected requests.
- API and runner bearer authentication and GitHub webhook signature checks reject
  non-ASCII headers without raising a server error.
- GitHub metadata and artifact downloads stop reading at the ingestion limit and
  close rejected streams instead of buffering an entire response before checking it.
- CI actions are pinned to commit hashes. Checkout credentials are not persisted,
  and Python and npm vulnerability audits are required checks in the workflow.

## Scope

The application still uses one workspace trust domain. Live model inference requires
provider credentials. Imported repository execution requires a separately isolated
disposable Linux VM. No new model-quality or production-scale claim is made.

The regression tests exercise rejected requests, valid same-origin requests, stream
termination, and runner authentication without executing imported repository code.

## Local verification

Verified on Windows with Python 3.11.5 and Node 22.20.0:

- All 90 Python tests passed, including 22 new security regression cases.
- The frontend production build and formatting checks passed.
- Python lint and formatting checks passed.
- npm audit reported zero vulnerabilities. pip-audit reported no known vulnerabilities
  in installed dependencies; the editable FailureLab package was excluded from the
  package-advisory lookup.

One upstream Starlette/AnyIO test-client deprecation warning remains. Runner HTTP
contract tests do not establish that a disposable Linux VM deployment was exercised.
