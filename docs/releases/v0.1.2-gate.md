## Implementation changes

Provider transport/HTTP failures now have a distinct exception and sanitized event.
Invalid model output has a separate exception. The live harness reports
`provider_unavailable`, `agent_failed`, or `test_harness_failed`; no failure becomes
a deterministic fallback. Provider response bodies and request headers are not
written to application error events.

The live acceptance script freezes evidence before inference and retains checkpoint
values, source hashes, original diagnosis text, plans, provider and model identifiers,
tool metadata, usage, errors, and artifact associations. Original partial outputs
remain under their own acceptance IDs. Exact source bytes for those runs were
recovered using their recorded hashes and retained locally after later type and
replay changes; the original records were not edited.

Completed replay now preserves the case timestamp as well as its result. Missing
completed checkpoints, mismatched reports, and wrong case identities fail closed.
Pending checkpoints reject changed tool schemas. Existing pending checkpoints that
lack this metadata require a new investigation; their provenance is not relabeled.

The Compose default now matches the verified model. `failurelab --version` reports
the package version without loading provider configuration. Mypy runs in CI using
locked development tooling. Type annotations and explicit webhook evidence
construction correct the application type errors. Narrow dependency declarations
cover only the methods used by optional adapters; import/type errors remain enabled.
Those declarations do not validate the optional integrations at runtime.

## Security and deployment scope

Tests cover webhook authentication/deduplication, archive and path bounds,
credential stripping on artifact redirects, runner authentication/allowlisting,
manifest constraints, immutable assertion identity, artifact integrity, model call
budgets, citation constraints, and forbidden interventions. Local HTTP webhook
replay again returned 401 for unsigned/tampered bodies, accepted a signed body,
and reused its investigation on duplicate delivery.

Docker Desktop, `docker`, PostgreSQL server, and `psql` are absent from this Windows
environment. No PostgreSQL connection is configured. The Docker/PostgreSQL deployment
smoke test was therefore not executed. The documented PostgreSQL path uses the
optional extra and initializes application/checkpoint schemas; Compose currently
deploys the SQLite application, not a PostgreSQL service.

No permanent runner URL, webhook secret, or public application endpoint is
configured. Public GitHub webhook delivery and a permanent private runner remain
unverified. The earlier disposable Linux execution applies only to the reviewed
owned fixture. Arbitrary untrusted repositories and production deployment remain
outside the verified scope. No public endpoint, tunnel, database service, or release was
created for this check.

are under ignored `var/live-acceptance/<acceptance-id>/`. The measurement record maps
each artifact hash to its investigation. Runtime databases, credentials, account
metadata, and raw trace archives are excluded from publication.

scorer or fixture:

```powershell
uv run python scripts/verify_live_agents.py
```

```powershell
uv run python scripts/verify_unfamiliar_incident.py run --attempt 3
```
